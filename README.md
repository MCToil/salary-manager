# 給与管理 (salary-manager)

**https://mctoil.github.io/salary-manager/**

給与明細を月ごとに管理する単一 HTML アプリ。データは端末の localStorage に保存され、外部サーバには送信されません（画像解析時の api.anthropic.com、同期時の api.github.com を除く）。

## 起動

上のアドレスを開くだけです。iPhone では Safari で開いて「ホーム画面に追加」しておくと、アプリのように使えます。

ローカルで動かす場合は `index.html` を直接開くか、次を実行します。

```bash
python3 serve.py
```

→ http://localhost:3500

データは端末・オリジンごとに保存されるので、公開アドレスとローカルは別のデータになります。両方で使う場合は同期の設定をそれぞれに入れてください。

## 機能

| タブ | 内容 |
|---|---|
| 一覧 | 年間サマリ（総支給／控除／手取り）と月別カード。カードをタップで編集 |
| 入力 | 手動入力。支給・控除・勤怠の小項目を自由に追加。過去に使った項目名をサジェスト |
| 画像取込 | 給与明細画像から自動入力（2 経路。下記） |
| 集計 | 月別推移グラフ、小項目別の年間クロス集計 |
| 設定 | API キー、解析モデル、小項目マスタ、JSON/CSV 書き出し・復元 |

合計欄は空欄なら小項目から自動計算。明細記載値を入れた場合、小項目合計とズレると警告が出ます。

## 画像から自動入力する 2 つの方法

### A. アプリから直接（API キーあり）

1. 設定タブに Anthropic API キー（`sk-ant-...`）を登録
2. 画像取込タブに明細画像をドラッグ＆ドロップ（複数ページ可）
3. 「解析して入力」→ Claude が読み取り、小項目まで自動生成して入力フォームに反映
4. 内容を確認して保存

- JSON Schema で構造化出力を強制。読めない箇所は推測せず 0 + メモに記録するよう指示済み
- キーは localStorage にのみ保存。送信先は `api.anthropic.com` のみ
- 解析後に実費（USD）が表示されます

### モデル選択

設定タブで切り替えられます。両モデルとも高解像度ビジョン（長辺 2576px）対応。

| モデル | 単価 (per MTok) | 明細 1 枚 | 画像の長辺上限 | 備考 |
|---|---|---|---|---|
| `claude-opus-5`（既定） | $5 / $25 | 約 9 円 | 2576px | 読み取り精度優先 |
| `claude-sonnet-5` | $2 / $10 → **$3 / $15**（2026-09-01〜） | 約 4〜6 円 | 2576px | 低コスト |
| `claude-haiku-4-5` | $1 / $5 | 約 1 円 | **1568px** | 実験用。読み違いに注意 |

Sonnet 5 の $2/$10 は 2026-08-31 までの導入価格で、9/1 に定価へ戻ります（アプリ内のコスト表示も自動で切り替わります）。年 12 枚なら Opus と Sonnet の差額は 70 円程度なので、迷うなら既定の Opus 5 のままで問題ありません。

**Haiku 4.5 の注意**: 高解像度ビジョン以前の世代のため、画像が長辺 1568px に縮小されてから読まれます。小さな漢字や桁の取り違えが起きやすいので、保存前に数字を必ず突き合わせてください。アプリ側でも、Haiku で読み取った結果には警告を表示します。なお Haiku 4.5 は `effort` パラメータに非対応のため、リクエスト時に自動で省いています。

AI 取込した明細には使用モデルが記録され、一覧のバッジ（`Opus 5` / `Sonnet 5`）に表示されるので、精度の比較ができます。

### B. Claude Code 経由（API キー不要）

1. 画像取込タブの「スキーマをコピー」を押す
2. Claude Code に明細画像とコピーした内容を渡す
3. 出力された JSON を「JSON 取込」に貼って取り込む（複数月の配列も可）

## データ形式

```json
{
  "ym": "2026-07",
  "kind": "bonus",
  "label": "夏季賞与",
  "payDate": "2026-07-10",
  "company": "株式会社◯◯",
  "earnings":   [{ "name": "賞与",         "amount": 600000 }],
  "deductions": [{ "name": "健康保険料",   "amount": 30000 }],
  "attendance": [{ "name": "出勤日数", "amount": 21, "unit": "日" }],
  "totals": { "gross": 600000, "deduction": 30000, "net": 570000 },
  "note": ""
}
```

- 控除額は正の数
- `totals` が 0 の項目は小項目から自動計算
- 保存時に `source`（`manual` / `ai` / `import`）と `model` が自動で付きます

### 種別と重複の扱い

明細の同一性は **`ym` + `kind` + `label`** で判定します。

| `kind` | 意味 |
|---|---|
| `salary` | 通常の月給（既定） |
| `bonus` | 賞与・ボーナス |
| `other` | 臨時支給（一時金・調整支給など） |

同じ月でも**種別か名称が違えば別の明細**として共存します。7月の給与と7月の賞与、さらに決算一時金を同時に登録できます。3つすべてが同じ組み合わせのときだけ上書きになります。

年間サマリと月別推移グラフは、同じ月の複数明細を**合算**します。小項目別のクロス集計は明細ごとに列が分かれます（`7月` / `7月 夏季賞与`）。

画像から取り込む場合、表題が「賞与明細」等であれば `kind` は自動で `bonus` になり、「夏季賞与」のような固有名称は `label` に入ります。

## iPhone と Mac で同期する

経費台帳と同じく、**GitHub の非公開 Gist** 経由で同期します。新しいサービスの登録は不要で、**トークンは経費台帳のものを使い回せます**（保存先の Gist だけ別になります）。

### 設定

1. GitHub → Settings → Developer settings → Personal access tokens → **Tokens (classic)** でトークンを発行。スコープは `gist` のみ
2. 1台目: 設定タブの同期カードにトークンを貼り「保存して同期」→ 非公開 Gist が自動生成される
3. 「Gist ID をコピー」でIDを取得
4. 2台目: 同じトークンと Gist ID を貼って「保存して同期」

### 動作

- 明細やマスタを変更すると **2.5秒後に自動で同期**
- アプリを表示したタイミングでも自動確認（10秒に1回まで）
- 画面上部のバーに状態を表示（緑=同期済み / 橙=未同期の変更あり / 赤=エラー）
- 「今すぐ同期」で手動実行

### 同期される範囲

| | 同期 |
|---|---|
| 明細（records） | ✅ |
| 小項目マスタ | ✅ |
| **Anthropic API キー** | ❌ 端末ごと |
| **解析モデルの選択** | ❌ 端末ごと |
| GitHub トークン / Gist ID | ❌ 端末ごと |

API キーは Gist に**一切送信されません**。

### 競合したとき

両方の端末に前回同期以降の変更がある場合、どちらを残すか選ぶダイアログが出ます（自動マージはしません）。クラウド側を取り込む際は**直前の状態を1世代だけ退避**するので、「取り込み前のデータに戻す」で戻せます。

### 注意

- トークンはこの端末の localStorage にのみ保存されます。共用端末では使わないでください
- 不要になったら「この端末の同期を解除」＋ GitHub 側でトークンを失効
- 同期設定がある状態で「全データ削除」を実行しても、クラウドは消えません（次回同期でクラウドの内容が戻ります）。クラウドごと消すには先に同期を解除してください

## バックアップ

設定タブの「JSON 書き出し」で全データを保存、「JSON 復元」で戻せます。同期を使っていても、Gist ごと失う事故に備えて定期的な書き出しを推奨。
